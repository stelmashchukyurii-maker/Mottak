# HANDOFF — 09.08.2026 kl. 00:04

## Approved business rules

This handoff records the user-approved warehouse model and the production repairs made after the review of `mottak_scans` / `ut_test_stock`.

### 1. Tag identity
- `lower_number` is the current tag identifier (exactly 6 chars A-Z / 0-9).
- The old fixed `078500` / `upper_number` is not business data and is not used for identification.
- `upper_number` remains physically present only for backward compatibility and must stay blank.
- One current database row is reused per `lower_number`; history of repeated product usage is not required at this stage.

### 2. Product
`product` is the tag's CURRENT product assignment:
- `bunner`
- `hyller30`
- `hyller60`

If a previously dispatched tag returns, the same row is reused and `product` is overwritten with the newly selected product.

### 3. Warehouse lifecycle — exactly three stock states
Only these values are allowed:
- `in_stock` = På lager / На складі
- `staged` = På rampe / На рампі
- `dispatched` = Sendt / Відправлено

`reserved` is removed from the business model and database constraints.

Actual physical flow:
1. Goods are moved to the ramp.
2. They are scanned there.
3. That scan immediately changes the specific tag from `in_stock` to `staged` and links `ut_order_id`.
4. Order-level `Klar på rampe` confirms completeness; it does not perform a delayed reserved->staged transition.
5. Final dispatch changes `staged` to `dispatched`.

### 4. Repeat receipt
When a tag is received again:
- If current state is `in_stock`: block as already on stock.
- If current state is `staged`: block as already on a ramp.
- If current state is `dispatched`: reuse the same row, overwrite current product, return to `in_stock`, clear order/ramp/dispatch linkage and use the new receipt/photo.

### 5. WORKING vs GREEN vs UT TEST
- WORKING and normal GREEN are parallel UI/code routes over the SAME normal production database.
- Normal GREEN must use `mottak_scans`, `ut_orders`, `ut_order_scans`, `ut_order_items` directly.
- Dedicated UT TEST is the only isolated contour. It continues to use `ut-test-api.js`, which maps to `ut_test_stock`, `ut_test_orders`, `ut_test_order_scans`, `ut_test_order_items` and test RPCs.
- `green-ut-api.js` is now only a compatibility marker and does not rewrite requests.
