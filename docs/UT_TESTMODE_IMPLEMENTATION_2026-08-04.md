# BaMavaremottak — UT TESTMODUS

**Дата:** 04.08.2026, 20:31 CEST  
**Статус:** чинне доповнення до `docs/UT_PROTOCOL_2026-08-04.md`  
**Напрям:** складська сторінка UT, реальне тестове списання та повне повернення

## 1. Головне рішення

LIVE-режим зараз не реалізовується і не показується користувачу.

Усі поточні UT-завдання є тестовими:

```text
резервування
→ постановка на рампу
→ реальне тимчасове списання з фізичного залишку
→ контроль цифр
→ обов’язкове повернення всіх товарів у in_stock
```

UT не видаляє рядки `mottak_scans`, фотографії, EPC, верхній або нижній номер.

## 2. Нові файли

- `utsending-v5.html` — складська TEST-форма;
- `supabase-ut-test-mode.sql` — додаткові поля та RPC-функції тестового списання/повернення.

Базові сторінки `utsending.html` і `utsending-v4.html` залишені як технічна основа та історія.

## 3. Обов’язкове встановлення SQL

Перед використанням `utsending-v5.html` потрібно один раз виконати весь файл:

```text
supabase-ut-test-mode.sql
```

у Supabase SQL Editor.

Після успіху SQL повертає контрольний фізичний залишок через:

```sql
select * from public.ut_physical_stock();
```

## 4. Нові поля `ut_orders`

- `is_test` — зараз завжди `true`;
- `test_state`: `active`, `dispatched`, `returned`;
- `test_dispatched_at`;
- `test_returned_at`;
- `test_before_bunner`;
- `test_before_hyller`;
- `test_after_dispatch_bunner`;
- `test_after_dispatch_hyller`;
- `test_after_return_bunner`;
- `test_after_return_hyller`.

## 5. Фізичний залишок

Фізично на складі рахуються підтверджені записи зі станами:

```text
in_stock + reserved + staged
```

`dispatched` не входить у фізичний залишок.

Тому резервування та рампа ще не зменшують фізичну кількість. Зменшення відбувається лише під час тестового списання.

## 6. RPC-функції

### `ut_physical_stock()`

Повертає загальну фізичну кількість:

- Bunner;
- hyller.

### `test_dispatch_ut_order(order_id)`

Дозволена лише для повністю укомплектованого завдання у статусі `staged`.

Виконує:

```text
staged → dispatched
status → completed
test_state → dispatched
```

Перед і після зміни записує фізичний залишок у поля завдання.

`completed` тут є лише технічним проміжним статусом TEST. Це не LIVE-відправлення.

### `return_ut_test_order(order_id)`

Дозволена лише після тестового списання.

Виконує:

```text
dispatched → in_stock
ut_order_id → null
reserved_at → null
staged_at → null
dispatched_at → null
status → cancelled
test_state → returned
```

У `ut_order_scans` записується:

```text
released_reason = TEST_RETURNED_TO_STOCK
```

Історичний `dispatched_at` у `ut_order_scans` зберігається як доказ, що тестове списання відбулося.

## 7. Інтерфейс `utsending-v5.html`

Сторінка показує великий банер:

```text
TESTMODUS — INGEN LIVE-UTSENDING
```

Звичайна кнопка фінального відправлення замінена на:

```text
Тестово списати всю рампу
```

Після списання показуються:

- фізичний залишок до списання;
- фізичний залишок після списання;
- списана кількість Bunner;
- списана кількість hyller.

Потім доступна єдина кнопка:

```text
Returner alle varer til lager
```

Після повернення показуються:

- залишок до тесту;
- залишок після списання;
- залишок після повернення;
- різниця після повернення;
- зелений результат, якщо початковий залишок відновлений.

## 8. Безпечний порядок тесту

```text
1. Виконати supabase-ut-test-mode.sql.
2. Відкрити utsending-v5.html.
3. Зафіксувати «FYSISK PÅ LAGER NÅ».
4. Прийняти завдання.
5. Почати роботу.
6. Знайти й зарезервувати всі товари.
7. Поставити всю рампу на рампу.
8. Поставити контрольну галочку.
9. Натиснути «Тестово списати всю рампу».
10. Перевірити реальне зменшення фізичного залишку.
11. Не закривати тест як завершений назавжди.
12. Натиснути «Returner alle varer til lager».
13. Перевірити, що різниця після повернення дорівнює нулю.
```

## 9. Важливі обмеження

- Форма не повинна використовуватися до виконання нового SQL-файлу.
- LIVE-режиму немає.
- Не використовувати стару кнопку `Bekreft utsending` на базовій сторінці.
- Для тесту відкривати саме `utsending-v5.html`.
- Якщо тест списано, але ще не повернуто, товар має `stock_status=dispatched` і фізичний залишок зменшений. Потрібно відкрити це саме завдання та натиснути повернення.
