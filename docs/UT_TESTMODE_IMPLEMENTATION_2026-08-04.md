# BaMavaremottak — UT RAMPE + TESTMODUS

**Дата:** 04.08.2026, 20:48 CEST  
**Статус:** чинне доповнення до `docs/UT_PROTOCOL_2026-08-04.md`  
**Напрям:** офісна рампа, складське підтвердження, реальне тестове списання та повернення

## 1. Основне рішення

Окрема робоча тестова сторінка більше не використовується.

Основні сторінки проєкту:

```text
bestilling.html — офіс створює рампу
utsending.html  — склад підтверджує рампу
```

Головне меню вже веде на ці адреси.

Старе посилання `utsending-v5.html` автоматично перенаправляє на `utsending.html`.

LIVE-режим зараз не показується і не використовується.

## 2. Правило рампи

```text
Одна рампа = одне нове комбіноване UT-завдання
```

Одне завдання може одночасно містити:

- Bunner;
- Hyller x30;
- Hyller x60.

Приклад одного рядка `ut_orders`:

```text
ramp = 32
bunner_stacks = 2
hyller30_sets = 1
hyller60_sets = 3
```

Офісна форма блокує створення другого активного завдання на ту саму рампу.

Старі дублікати, які вже існують у базі, не видаляються. На обох сторінках вони візуально групуються під однією карткою рампи як окремі старі записи.

## 3. Офісна сторінка `bestilling.html`

Версія:

```text
UT Kontor v12 RAMPE
```

Офіс вводить:

1. номер рампи;
2. кількість стопок Bunner;
3. кількість комплектів Hyller x30;
4. кількість комплектів Hyller x60;
5. необов’язковий коментар.

Поля майбутнього показуються неактивними:

```text
Mottaker — senere
Adresse — senere
Dato — senere
CMR — senere
```

Після натискання:

```text
Send hele rampen
```

створюється один комбінований запис `ut_orders`.

Редагування дозволене лише поки статус завдання `new`.

## 4. Складська сторінка `utsending.html`

Версія:

```text
UT Bekreftelse v6 RAMPE
```

Головний список згрупований за номером рампи.

Нове нормальне завдання має одну картку рампи та один внутрішній запис.

Старі дублікати рампи показуються всередині однієї картки як декілька старих записів.

Статуси для користувача спрощені:

```text
Ny
I arbeid
Test trukket
Test returnert
Stornert
```

## 5. Ідентифікація товару

На складській сторінці доступні:

```text
Фото — активне
Вручну — активне
Nordic ID — пізніше
```

Фото поки використовується як візуальна перевірка. Верхній і нижній номери вводяться вручну.

Пошук виконується за точною парою:

```text
upper_number + lower_number
```

Після безпечного пошуку викликається `reserve_ut_scan`.

## 6. Підтвердження цілої рампи

Після реєстрації всіх потрібних товарів працівник ставить одну контрольну галочку та натискає:

```text
Bekreft hele rampen og testfratrekk
```

Одне натискання виконує:

```text
stage_ut_order
→ test_dispatch_ut_order
```

Тобто всі товари цієї рампи разом переходять:

```text
reserved → staged → dispatched
```

Після цього фізичний залишок реально зменшується.

## 7. Повернення цілої рампи

Після тестового списання з’являється кнопка:

```text
Returner hele rampen til lager
```

Вона викликає:

```text
return_ut_test_order
```

і повертає всі товари цього завдання:

```text
dispatched → in_stock
ut_order_id → null
reserved_at → null
staged_at → null
dispatched_at → null
```

Записи `mottak_scans`, фотографії, EPC, верхній і нижній номери не видаляються.

Історія залишається в `ut_order_scans` із:

```text
released_reason = TEST_RETURNED_TO_STOCK
```

## 8. Обов’язковий SQL

Перед першим тестовим списанням потрібно один раз виконати весь файл:

```text
supabase-ut-test-mode.sql
```

у Supabase SQL Editor.

Без нього:

- групування за рампою;
- комбіноване офісне завдання;
- резервування;
- скасування до списання

можуть працювати, але кнопки реального тестового списання та повернення не матимуть потрібних RPC-функцій.

Сторінка `utsending.html` сама показує червоне попередження, якщо SQL ще не встановлено.

## 9. Фізичний залишок

Фізичний залишок рахується як:

```text
in_stock + reserved + staged
```

`dispatched` не входить до фізичного залишку.

Тому:

```text
резервування — не зменшує фізичний залишок;
постановка на рампу — не зменшує фізичний залишок;
тестове списання — зменшує фізичний залишок;
повернення — відновлює фізичний залишок.
```

## 10. Безпечний тест

```text
1. Виконати supabase-ut-test-mode.sql.
2. На bestilling.html створити одну невелику рампу.
3. На utsending.html відкрити цю рампу.
4. Натиснути Start hele rampen.
5. Знайти й зарезервувати всі товари.
6. Поставити контрольну галочку.
7. Натиснути Bekreft hele rampen og testfratrekk.
8. Перевірити зменшення FYSISK PÅ LAGER.
9. Натиснути Returner hele rampen til lager.
10. Перевірити, що різниця після повернення дорівнює нулю.
```
